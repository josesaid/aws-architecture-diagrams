Generative AI with RAG on Amazon Bedrock

An assistant that answers from your own documents. Lambda searches OpenSearch for the relevant chunks and sends them to an Amazon Bedrock model together with the question. Documents are ingested from S3.

Comments

  • The model does not know your documents. RAG adds the context retrieved from OpenSearch before generating the answer.
  • Embeddings must be generated with the same model during ingestion and querying. If you change models, you must reindex.
  • Review Bedrock's data handling policies and encryption options before loading sensitive information.
  • For repeated questions, a cache in DynamoDB reduces cost and latency.

Information flow

  1. Amazon API Gateway

    The user sends the question to API Gateway.

  2. AWS Lambda

    API Gateway invokes the Lambda function that orchestrates the RAG flow.

  3. Amazon OpenSearch Serverless

    Lambda searches the vector index for the most similar document chunks.

  4. Amazon Bedrock

    Lambda sends the question and the retrieved context to the Bedrock model.

  5. Amazon Bedrock + API Gateway

    Bedrock returns the answer, and the result reaches the user through API Gateway.

Note to consider

Cost grows with the amount of context you send to the model. Limit the number and size of retrieved chunks to balance quality and cost.
