Real time with AppSync and DynamoDB Streams

Data changes reach every connected user without the client polling again. AppSync receives the mutations, DynamoDB Streams detects the changes, and Lambda sends them back to AppSync, which pushes them over WebSocket to subscribed clients.

Comments

  • AppSync manages WebSocket subscriptions for you. If you need full control over the connection, API Gateway WebSocket is the alternative.
  • DynamoDB Streams delivers each table change in order, so there is no need to poll the database periodically.
  • Authenticate connections with Amazon Cognito or another identity provider. Without a valid token, AppSync does not open subscriptions.
  • Send only what changed in each event. Resending the full state on every change consumes bandwidth and raises cost.

Information flow

  1. AWS AppSync

    The user sends a GraphQL mutation to AppSync.

  2. Amazon DynamoDB

    AppSync writes the change to the DynamoDB table.

  3. DynamoDB Streams + AWS Lambda

    DynamoDB Streams emits the change and a Lambda function receives it.

  4. AWS Lambda

    Lambda sends the event back to AppSync.

  5. AWS AppSync

    AppSync pushes the event to subscribed clients over WebSocket.

Note to consider

Subscriptions are billed per connection and per message. Limit events to the clients that need them, using filters in the subscription.
